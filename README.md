# ClionLuogu

> 在 CLion 里一站式刷洛谷：**拉题 → 预览 → 写码 → 对拍 → 提交 → 看评测**。

[![Release](https://img.shields.io/github/v/release/JiangWanZhengChouYv/ClionLuogu?v=1)](https://github.com/JiangWanZhengChouYv/ClionLuogu/releases)

![CLion](https://img.shields.io/badge/CLion-2024.3%2B-blue)
![Platform](https://img.shields.io/badge/IntelliJ%20Platform-plugin-black)

一个运行在 **CLion** 上的洛谷插件：把拉题、预览、提交、看评测全搬进 IDE，不用在浏览器和编辑器之间来回切。

## 功能

窗口按用途分两处（底部那条第一次打开时，插件会替你开启 IDE 的**宽屏工具窗口布局**，让底部只占中间编辑区的宽度、不把左侧栏挤短；通知里可一键撤销，撤销后插件不会再打开）：**左侧「题目栏」6 个页签**（评测 / 拉取 / 搜索 / 预览 / 题目 / 登录），**底部「运行栏」3 个页签**（自测 / 对拍 / 提交）——写代码 → 跑 → 看输出是一条直线，跟 CLion 自己的 Run 窗口一个位置。

| 页签 | 能做什么 |
| --- | --- |
| **评测** | 提交历史 + 详情。详情区按子任务分行展示**逐测试点彩色方块**（正方形、自动换行、悬停看编号/状态/耗时/内存），并给出**各子任务得分合计**；当次提交的**源码可查看、可复制**，编译错误可**一键跳到出错行** |
| **拉取** | 输入题号 → 生成 `Pxxxx.cpp`、`Pxxxx.md` 与**全部样例**到 `Pxxxx_samples/` |
| **搜索** | 关键词搜题 → 结果列表 → 拉取选中；**双击结果直接预览题面** |
| **预览** | 题面 / **题解** 双模式：两种正文都走 **Markdown**（内置 marked.js）+ **LaTeX 公式**（内置 MathJax）+ 图片，样式跟随 IDE 明暗主题；切到「题解」按页拉取该题题解，已加载的题解以列表平铺、点一条看一篇 |
| **提交** | 确认题号 / C++ 语言版本、看代码预览、一键提交（需要时弹验证码） |
| **对拍** | **现场编译** `Pxxx.cpp` 后把 `Pxxxx_samples/Pxxxx_N.in` 逐组喂进去与 `.out` 比对；每组时限与内存上限可以自己填，**默认取题面**（`Pxxx.md` 里那两行）；**时限只算运行、不含编译**（编译另有 120 秒上限，概览里分开显示）；超内存判「超内存」，颜色同评测页 MLE；失败那组给**首个差异行 + 两侧上下文**、退出码与 stderr，还能一键**存反例**（输入 / 期望 / 实际写到 `Pxxx_cases/`）；编译失败时列表第一行就是完整诊断，其余组标「未执行（编译失败）」，诊断里可**一键跳到出错行** |
| **自测** | 底部运行栏第一页：**现场编译** `Pxxx.cpp`，把**你手打的输入**喂进去。三栏：**左输入 / 中 stdout / 右概览+stderr+编译诊断**。没有 `Pxxx_samples/` 也能跑（对拍页在这种情况下直接没得跑，而「造个输入看看它打印什么」正是调 WA 的第一步）。输入**按题号记住**（项目级 XML，不落盘成文件），换题号自动切各自那份；每次点「运行」都**先重编**；编译失败时诊断摊在下方，旁边有**跳到出错行**。**不报内存**——子进程内存没有可移植的拿法，宁可不说 |
| **题目** | 本地题库索引：按题号列出项目根下的 `Pxxx.cpp` / `Pxxx.md` / `Pxxx_samples/` / `Pxxx_cases/` 与最近一次评测结果（颜色同评测页、带得分），勾「只看未提交」挑出提交过却还堆着的题；选中点**「删除本题文件」**，弹一次确认列清要删什么再动手（提交记录保留） |
| **登录** | 填 `__client_id` / `_uid`（从浏览器 Cookie 复制），也支持退出登录 |

- **本地对拍**：拉题落盘的样例终于不只是摆在那里——提交前先在本地编译并跑一轮，省掉一次排队评测。**用的就是你 CLion 项目实际在编的那个编译器**（读自 CMake 自己写的 `CMakeCache.txt`，优先级：插件设置里填的绝对路径 > CLion 选的 > PATH 上的 `clang++`/`g++`/`c++`，Windows 再退到 IDE 自带的 MinGW），「编译器」那一行会写明用的是谁、从哪来的，悬停看绝对路径与版本首行；**默认模板的头文件跟着编译器走**（clang → 真实标准头，GCC → `bits/stdc++.h`）。产物写在系统临时目录、不进你的仓库，也不用先手动 Build；每组固定 5 秒时限、输出超限即刻终止，死循环与刷屏都不会把 IDE 撑爆。
- **自测（底部运行栏第一页）**：比「造一组输入自己跑一下」更轻的入口——没有 `Pxxx_samples/` 也能跑，输入框里打什么就喂什么，程序读完立刻拿到 EOF（走的是文件重定向，不是管道，所以不会因为「写完没关」或「输入太大把管道塞死」卡住）。输出用与对拍同一套详情区：等宽、不折行、能用鼠标选。输入**按题号**存进项目级 XML，换题各归各的、重启还在；**不落盘成 `.in` 文件**，所以本地题库那套「只认四个精确名字」的删除口径一个字都不用改。每次「运行」都先重编，不给「用上次产物」的选项（那得靠 mtime 猜产物新旧）；**内存上限要这台机器量得到才生效**：插件实测外部 `time` 能不能解析出峰值（挨个试 `/usr/bin/true`、`/bin/true`… 而不是假设哪个一定在）。量不到时字段照样能填、值照样显示，但概览会写明「不生效」——不猜，也不拿 0 当「没超」。
- **失败组一键存反例**：选中那一行点「存反例」，把它的 `.in`、期望输出与实际输出一字节不改地写进项目根的 `Pxxx_cases/`（有 stderr 再多一个文件），直接喂调试器或本地重跑。详情区的差异上下文只截 ±20 行、单行截 200 字符——那是用来看的，不是用来调的。列表上方还有「只看失败」与「已跑 N 组 · 失败 M 组」的计数。
- **窄侧边栏自动换向**：工具窗口拉窄到 460 像素以下，「对拍」「题目」与「评测」页的列表 / 详情会从左右排自动改成上下排，拖宽又换回来；对拍行的耗时单独一列对齐。
- **评测未通过通知**：判成非 AC 终态（WA / RE / TLE / MLE / CE…）时右下角弹一条，点 **「查看」** 跳到评测页并选中该条记录；AC 仍只弹清理询问，不叠加通知。开关在 `Settings → Tools → 洛谷拉题`。
- **评测记录按项目持久化**（含源码、语言与编译错误详情），重启 IDE 不丢；评测没跑完就重启的记录，下次启动会**自动补轮询**一次（不弹通知、不弹清理框，只把结果刷回来）。
- **每日打卡提醒**：启动时查一次今日还能不能打卡，能则弹一条右下角通知，**点了通知里的「打卡」按钮才发请求**；错过通知可按侧边栏标题栏的打卡图标手动来一次，开关在 `Settings → Tools → 洛谷拉题`。
- **编译错误一键跳到出错行**：对拍页的编译诊断与评测页的 CE 详情旁边都有按钮，点开项目根的 `Pxxx.cpp` 落在第一条 error 上。只认提交文件那种行号（`Pxxx.cpp`、OJ 常用的 `Main.cpp`），标准库内部的（模板实例化、`<vector>` 里第 572 行）不跳；本地文件被改名 / 挪走、或行号超出当次提交的代码长度时**按钮直接不给**——宁可少跳一次，也不跳到一个错的地方。
- **各子任务得分合计**：详情区、方块区下方和「未通过」通知都会写「N 分」。**取不到分数时一个字符都不显示**（评测进行中的子任务没有分数，硬算会算出骗人的 0 分）；全 WA 的 0 分照常显示。不显示 `/满分`——那个字段在提交记录里根本没有。
- **本地题库索引（「题目」页签）**：刷过的题在项目根攒成一团时，这里按题号列清楚每题有哪几类产物、几个样例、最近一次评测是什么结果。「只看未提交」把已经提交过、文件却还堆着的挑出来；选中点「删除本题文件」，**弹一次确认、列出实际存在的待删项**再动手。删除只认项目根下 `Pxxx.cpp` / `Pxxx.md` / `Pxxx_samples/` / `Pxxx_cases/` 这四个精确名字——改过名、放进子目录的一律不碰，**提交记录与评测历史永远保留**。
- **AC 后清理**：某题评测变成 AC 时弹窗问一句，确认后删掉项目根下的 `Pxxx.cpp` / `Pxxx.md` / `Pxxx_samples/` / `Pxxx_cases/`（含其中全部文件，目录会递归删净）；提交记录保留，不想要提醒可在同一处关掉，错过询问就去「题目」页签手动删。
- **底部运行栏按「矮」重排**：三个页签的头部都只占一行（一件一行量出来 150px+，比窗口本身还高），预览 / 列表 / 详情吃满剩下的全部高度；「刷新预览」「重新查找样例」两个按钮取消了 —— 每秒自动重看与磁盘签名自动重探已经取代它们。三页各有各的图标。
- **外观跟随 IDE**：详情区分节显示（键值行 + 标题线），编译错误 / 编译器输出 / 提交的代码各自是**等宽、不折行、可横向滚动、可用鼠标选中复制**的文本块；13 种评测判定按**明暗两套主题**分别给色，「还没结果」是空心圈不是实心灰块；列表里题号加粗、记录号弱化、状态按判定染色；四个列表有空态提示，评测 / 题目 / 搜索结果列表**直接敲题号就能定位**。预览页样式在 `src/main/resources/css/preview.css`，字号字体与配色都从当前主题取。
- **预览页照洛谷的写法适配**：题面正文（背景 / 描述 / 输入输出格式 / 提示）与题解走同一条 Markdown 管线——洛谷的题面用的是他们自己那套方言，`[文字](链接)`、`- 列表` 不交给 marked 就按字面显示。公式先占位保护再解析，所以 `$a_1 * b_2$` 不会被吃成斜体。题面头部「难度 / 时间限制 / 内存限制 / 分数」是一行一枚，**分隔符写在标记里**（`难度：普及-`），所以复制出来的纯文本也不会粘成一句。链接**摘掉 `href`、去处留在悬停提示**——这块正文嵌在 IDE 面板里，一点就把整块预览导航到洛谷官网，还得重新双击回来。
- **没有 JCEF 也会说清楚**：JCEF 在 2026.x 是 `plugins/jcef-plugin` 里**延迟加载**的模块，插件启动后那几秒它可能还没初始化完。这时预览走纯文本兜底，顶上明写「此刻不可用，稍等重新双击这道题即可」，而不是假装这台机器永远没有。兜底里正文仍是原文（不是空白），也**不嵌任何脚本**——`JEditorPane` 会把 JSON 当正文打印出来。
- **mac 上用 clang 会提醒一次装 GCC**：洛谷评测机是 g++ + libstdc++，mac 自带的却是 Apple clang——`/usr/bin/g++` 其实也是 clang 的马甲（所以插件**只按 `--version` 判身份，不信文件名**）。检测到「这台 mac 当前用的不是 GCC」时右下角提一次，并常驻在「编译器」那行的悬停里：`brew install gcc`，注意 brew 装完的名字**带版本号**（`g++-16`，没有裸 `g++`），要让插件用上它就把它配进 CLion 的 CMake（`-DCMAKE_CXX_COMPILER=…/g++-16` 后重新配置一次项目）或直接填进插件设置。换成 GCC 之后不再提，拉题的头文件也会自动换成 `bits/stdc++.h`。
- **回车能办的事**：拉取页题号、搜索页关键词、登录页两栏（第一栏回车跳第二栏，第二栏才登录）、自测 / 对拍的时限与内存字段，敲回车即生效，不用挪鼠标点按钮。唯一故意不吃回车的是**提交页的语言下拉与「提交」按钮**——提交是写操作，必须实点一下。
- 拉下来的 `.md` 是**规范 Markdown**，用 IDE 自带的 Markdown 预览也能渲染公式。
- 评测轮询**按 rid 并发**，连续提交互不打断；网络请求全在后台线程，界面不卡。
- 侧边栏标题栏只有两个按钮：「清空提交记录」与「每日打卡」。

## 安装

1. 到 [Releases](https://github.com/JiangWanZhengChouYv/ClionLuogu/releases) 下载最新的 `ClionLuogu-x.y.z.zip`
2. CLion → `Settings / Preferences` → `Plugins` → 齿轮 ⚙ → **Install Plugin from Disk…** → 选中刚下载的 zip
3. 重启 CLion，左边条出现 **ClionLuogu**（题目栏）与底部一条 **ClionLuogu**（运行栏：自测 / 对拍 / 提交）。IDE 会记住你拖过的窗口布局，所以老用户升级后第一次可能要手动把图标拖到左边条，之后就固定了

> 提示：插件目录下**不要同时存在多个同 id 的版本**（例如手工留的旧版备份），否则可能加载到旧的那一份。

## 环境要求

- **CLion 2024.3+**（已在 2026.2 实测）
- 依赖 CLion 自带的 **Markdown 插件**与 **JCEF**（默认都启用）

## 使用

1. **登录**：浏览器 `F12` → `Application` → `Cookies`，复制 `__client_id` 与 `_uid`，填进「登录」页。
2. **搜题 / 拉题**：搜索页输入关键词 → 双击某条**预览题面**，或选一条点「拉取选中」生成文件。
3. **写码**：打开生成的 `.cpp` 写代码，改完直接切到**底部**的运行栏——**不用先 Build**（插件自己调编译器，编辑器里没保存的那份会先落盘再编）。
4. **先自测**：底部「自测」页 → 确认题号 → 左边输入框打一组你自己造的 stdin → 「运行」（右边就是输出）。时间 / 内存上限在那一行可以自己改，空着就用题面的。下面就是 stdout / stderr / 退出码 / 用时；题没拉过、样例还没有也能跑，这一步不要求成对的 `.in/.out`。输入按题号记住，切到别的题再回来还在。
5. **再对拍**：底部「对拍」页 → 「编译并对拍」。左侧第一行是编译结果（失败就点它看完整诊断，旁边有**跳到出错行**），其余逐组判定；点某一行看**首个差异行**与两侧上下文、退出码与 stderr；勾「只看失败」只留问题组，选中失败行点「存反例」把反例落到 `Pxxx_cases/`；全绿了再去提交。
6. **提交**：底部「提交」页确认题号与语言 → 提交。要交的是哪一份写在预览旁边：**编辑器里打开的 `Pxxx.cpp`**（含未保存的修改）优先，编辑器里没开就退到**项目根那份磁盘文件**；两处都没有会直说「找不到 Pxxx.cpp」，不再拿「未打开编辑器」糊弄。预览**每 1 秒自动重看一次**，改完代码不用点「刷新预览」；内容没变就不重画，不会抢走你的滚动位置，面板切走时定时器自动停。
7. **看评测**：切到「评测」页，详情区会显示逐测试点的彩色方块与**各子任务得分合计**，悬停查看耗时 / 内存；判成非 AC 时右下角会弹通知，点 **「查看」** 直接跳回这条记录；是编译错误就点「跳到出错行」回到代码。
8. **看题解**：预览页点「题解」→ 上方列表点一篇看正文 → 「加载更多」翻下一页（需已登录）。
9. **打卡**：启动后若今日未打卡，右下角会弹通知，点 **「打卡」** 才会真的发请求；错过了就按侧边栏标题栏上「清空提交记录」旁边的**打卡按钮**（✓）手动来一次。
10. **AC 后清理**：评测变绿的瞬间会弹窗问「删除本题文件？」，列出实际存在的 `Pxxx.cpp` / `Pxxx.md` / `Pxxx_samples/` / `Pxxx_cases/`；点「删除」即清掉，点「保留」什么都不动。
11. **收拾工作区**：切到「题目」页 → 列表按题号列出本地都有哪几类产物、最近一次评测结果；勾「只看未提交」看那些还没提交过的题，选中点「删除本题文件」→ 确认框里列清楚要删什么 → 「删除」。

## 已知限制

- 题面里的**图片需要联网**加载。
- **题解需要登录**：洛谷的题解接口未登录一律返回 401，未填 Cookie 时「题解」会提示先登录。
- **打卡没有状态查询接口**：入口只在旧版首页服务端渲染，插件靠「页面里还有没有 `[name=punch]` 打卡按钮」判断（打过卡按钮就消失）。你要是先在网页上打了卡，插件当天仍可能提醒一次——点下去只会得到服务器「已经打过卡」的提示，不会重复打卡。
- 题面中**字面意义的 `$`**（非公式）可能被当成公式定界符，个别题目可能出现误判。
- 登录与验证码都需要**你本人**参与；插件不做自动登录。
- **删除只认四个精确名字**：项目根下的 `Pxxx.cpp` / `Pxxx.md` / `Pxxx_samples` / `Pxxx_cases`。改过名、挪进子目录、或一题写了好几份代码的，插件都不会去碰——删除不可逆，宁可少删。「题目」页签的索引用的是同一套口径（**只看根目录一层**），所以列出来的就是能删的，没列出来的它也不敢删。
- **跳行只跳到「自己那份提交」**：诊断里指向标准库内部（模板实例化、`<vector>` 的某行）的行号一律不给按钮；本地 `Pxxx.cpp` 不在项目根、或诊断的行号已经超过当次提交的代码长度，也不跳。要看的还是编辑器里那条真错误。
- **对拍不复用你项目的 CMake 配置**：它**复用 CLion 选的那个编译器**（从 `CMakeCache.txt` 里读 `CMAKE_CXX_COMPILER`），但只把 `Pxxx.cpp` **单个文件**交给它，参数用设置里那套（默认 `-std=c++17 -O2 -w`），不是 CMake 算出来的那套。项目里的自定义 `-D` 宏、多个 `.cpp`、第三方库、`-I` 路径，插件一概不知道——多文件题会报「undefined symbols / undefined reference」这类链接错，这是设计取舍，不是插件在复刻你的构建。
- **本地编译器不等于洛谷的评测机**：macOS 上默认跑的是 Apple clang + libc++，洛谷是 g++ + libstdc++（1.8.2 起插件会提醒装 GCC，并把头文件按编译器给）。已实测到的差异：`cout << __int128` 在 libc++ 上编不过（g++ 有那个重载）；`-O2` 下未定义行为的表现也可能不同。对拍只是提前抓错，**最终以提交给洛谷的结果为准**。
- **`bits/stdc++.h` 不做兼容**：那是 GNU/libstdc++ 专有的头，插件不再塞兼容头，默认模板直接列真实标准头。之前拉下来的老文件第一行还写着 bits，本地对拍会报 `file not found`——把那一行换成 `<iostream>` `<vector>` `<algorithm>` 等即可（诊断里也会提醒你）。
- **对拍不做特殊判定（SPJ）**：比较口径只忽略行尾空白与文件末尾空行，逐行严格对齐。洛谷用 SPJ 的题（答案不唯一）会出现「本地判错、OJ 判对」，这不是 bug。
- **对拍需要项目已落盘**：新建但还没保存到磁盘的项目没有 `Pxxx_samples/`，也没有 `Pxxx.cpp` 可编。
- 仅支持**一份已保存的登录态**，没有多账号切换。
